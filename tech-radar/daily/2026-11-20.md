## 🔥 1. 今日技术热点：Baseline 作为新"兼容性锚点"接管 Browserslist 时代

**是什么**
Web 平台的 Baseline（web.dev + MDN + WebDX 社区组推动）正在成为前端工程化新的兼容性基线。它把特性状态分为 `widely available`（跨主流浏览器稳定 30 个月以上）和 `newly available`（跨主流浏览器都已支持但未满 30 个月）。2026 年起，ESLint / Stylelint / 构建器插件生态（如 `eslint-plugin-compat-baseline`、`stylelint-plugin-baseline`，名称/版本待验证）已支持直接把 Baseline 年份作为检查目标。

**解决的旧痛点**
- `browserslist` 用"市场份额 + 浏览器版本"定目标，跨 CSS/JS/HTML 三种语言无法统一；维护者必须自己查 Can I Use。
- 团队里经常出现"PM 说要支持 Safari 15，但 CSS 用了 `:has()`" 这种隐藏风险，code review 看不出来。
- 版本号驱动的目标让升级决策很沉重："是不是要支持某 Chrome 旧版？"永远吵不完。

**底层原理 / 关键设计**
- 数据源是 npm 包 `web-features`：每个特性带 `baseline: "high" | "low" | false`、`baseline_low_date`、`baseline_high_date` 等机器可读字段。
- 工具链链路：**web-features → BCD（Browser Compat Data）→ 具体 lint 插件**。Stylelint 扫到 `@scope` 时查到它 `baseline: "low"`，若配置要求 `widely` 就报警。
- 配置表达从 `"Last 2 Chrome versions"` 变成 `"baseline-widely-available"` 或 `"baseline 2024"`——语义是"我愿意用 2024 之前已广泛可用的特性"。

**对日常工作的影响**
- `browserslist` 不必立刻废弃，新增 `baseline` 查询可和它并存；CI 跑 `stylelint --report-baseline-violations`（具体 flag 待验证），把特性风险前置到 PR。
- 和 PM/设计沟通时，"Baseline 2024" 比 "Safari 15.4+" 更直观。
- 坑点：Baseline 只覆盖**主流浏览器**（Chrome/Edge/Firefox/Safari），对国内 WebView（微信、UC、QQ）无能为力，仍需独立评估。

## 📘 2. 一个值得掌握的概念：浏览器资源提示的优先级与时序

**是什么**
`<link rel="preload|prefetch|preconnect|modulepreload|dns-prefetch">` 加 `fetchpriority` 属性，是一组**显式指挥浏览器资源调度**的提示。它们不是"下载更快"的魔法，而是在浏览器本就要下载的队列里调整时序/优先级。

**为什么需要**
HTTP/2、HTTP/3 多路复用下，连接数不再是瓶颈，**优先级与发起时机**成为关键变量。LCP 图片比首屏 JS 更重要，但浏览器默认不知道；一条下一步的数据将被用到，这些业务语义浏览器推断不了。

**怎么实现（关键机制）**
- **preconnect**：提前完成 DNS → TCP → TLS，节省首个请求 100–300ms（受网络影响）。
- **dns-prefetch**：只做 DNS，适合超多第三方域且不一定命中的场景。
- **preload**：告知浏览器"这个资源很快会被 use"，以当前文档优先级提前拉取，必须配 `as`。
- **modulepreload**：针对 ESM，会**预编译并构建依赖图**（提前解析 import tree）。
- **prefetch**：最低优先级预取，供下一导航使用，常被 BFCache / HTTP cache 共用。
- **fetchpriority**：对 `<img>` / `<link>` 直接标 `high | low | auto`，让 LCP 图片优先、第三方头像延后。

**边界与误区**
- 滥用 preload 会**挤占**真正关键路径带宽，首屏反而更慢。
- `preload as="script"` 必须与真正加载时的 MIME 严格一致，否则 double-fetch。
- `prefetch` 不保证被执行；`<link rel="prefetch" as="document">` 做下一页预取要考虑用户流量成本。
- DevTools → Network → Priority 列可直接验证，`<img fetchpriority="high">` 会从 Low 提升到 High。

## 🧩 3. 深度面试题：实现一个最小 Observable（of / map / filter / take）

**题干**
支持下列代码：
```js
const src = Observable.of(1, 2, 3, 4, 5)
  .map(x => x * 2)
  .filter(x => x > 4)
  .take(2)

const unsub = src.subscribe({
  next: v => console.log(v),   // 输出 6, 8
  complete: () => console.log('done')
})
```

**追问 1**：`Observable` 和 `Promise` 最大的区别是什么？你的实现是"同步 push"还是"异步 pull"？
**追问 2**：怎么返回一个 `unsubscribe` 函数，之后 `next` 不再触发？
**追问 3**：`take(2)` 拿到第二个值后要立刻停止上游 `map/filter` 执行，怎么做到？

**参考答案**
```js
class Observable {
  constructor(producer) { this._producer = producer }
  static of(...values) {
    return new Observable(observer => {
      for (const v of values) { observer.next(v); if (observer.closed) return }
      observer.complete()
    })
  }
  subscribe(observer) {
    const safe = {
      closed: false,
      next: v => { if (!safe.closed) observer.next?.(v) },
      complete: () => { if (!safe.closed) { safe.closed = true; observer.complete?.() } },
      error: e => { if (!safe.closed) { safe.closed = true; observer.error?.(e) } }
    }
    this._producer(safe)
    return () => { safe.closed = true }
  }
  map(fn) {
    return new Observable(obs => this.subscribe({
      next: v => obs.next(fn(v)),
      complete: () => obs.complete(),
      error: e => obs.error(e)
    }))
  }
  filter(pred) {
    return new Observable(obs => this.subscribe({
      next: v => { if (pred(v)) obs.next(v) },
      complete: () => obs.complete(),
      error: e => obs.error(e)
    }))
  }
  take(n) {
    return new Observable(obs => {
      let count = 0
      this.subscribe({
        next: v => {
          if (count < n) { obs.next(v); count++ }
          if (count >= n) { obs.complete() }   // 通过 closed 回传给上游
        },
        complete: () => obs.complete(),
        error: e => obs.error(e)
      })
    })
  }
}
```

**考察点**：
- Observable 是**多值、可取消、同步/异步皆可**的 producer；Promise 是**单值、不可取消、必异步**——根本区别是"推送次数"和"可中断性"。
- 本实现是同步 push（`of` 内直接 for 循环推值）。
- `take` 的关键：`obs.complete()` 后 `safe.closed = true`，上游的 `for` 循环下次检查 `observer.closed` 立刻退出——这就是 RxJS "订阅树反向传播"的思想雏形。

## 🛠️ 4. 新工具/规范/API 速览：CSS `@scope`

**是什么**
`@scope (root) to (limit)` 是原生 CSS 的**作用域选择器**。它让一段规则只对 `root` 子树生效，并在触达 `limit` 子树时停止匹配。Chromium 已稳定，Safari/Firefox 跟进中（版本号待验证）。

**解决什么问题**
组件样式隔离长期靠 CSS Modules、BEM、Shadow DOM、Scoped CSS 预处理器。各方案要么需要构建工具，要么破坏可穿透性（Shadow DOM 隔离太彻底）。`@scope` 是**无需任何构建**的 CSS 原生方案。

**和已有方案对比**

| 方案 | 构建依赖 | 可被外部覆盖 | 嵌套组件边界 | 兼容性 |
| --- | --- | --- | --- | --- |
| BEM 命名 | 无 | 是 | 靠约定 | 全 |
| CSS Modules | 需 | 是（通过类名） | 不支持 | 构建器相关 |
| Vue/Svelte Scoped | 需 | 是（属性选择器） | 不支持 | 框架相关 |
| Shadow DOM | 无 | 否（完全隔离） | 原生 | 较好 |
| **@scope** | **无** | **是** | **原生 `to`** | **Chromium 稳定（待验证）** |

**写法示例**
```css
@scope (.card) to (.card .nested-card) {
  :scope { padding: 12px; }
  h2 { color: tomato; }  /* 只命中外层 .card，不穿透进 .nested-card */
}
```

**现阶段建议**：**观望偏积极**。可渐进增强——退化行为是样式失效，不会破坏页面。生产项目用它做"组件样式边界"时，配合 `@supports` 检测再降级。

## 📂 5. 源码阅读推荐：Koa 的 `application.js` 洋葱模型

**仓库路径**：`koajs/koa` 的 `lib/application.js`（约 250 行）与 `koajs/compose` 的 `index.js`（约 50 行）。

**核心思路（自己的话）**
Koa 全局就两件事：`Context`（把 req/res 封装成对象）和中间件数组。`compose(middleware)` 返回一个函数，内部用**递归 + Promise 链**让中间件按 `next()` 调用形成洋葱圈：进入时按顺序执行前半段，`await next()` 把控制权交给下一个；返回时按逆序执行后半段。整个请求就是对这棵嵌套 Promise 树的一次 await。错误处理靠顶层 try/catch 捕获整棵树抛出的任何异常，这就是 Koa 比 Express 异步错误处理优雅的根本原因。

**3 个阅读切入点**
1. `compose` 用一个 `index` 变量 + 递归保证"每个中间件的 `next` 只能被调用一次"，为什么？不加会怎样？
2. Koa 的 `ctx` 用 `Object.create` 继承原型，为什么不直接 `new Context()`？好处是什么？
3. `app.listen()` 为什么要把 `this.callback()` 作为 `http.createServer` 的 handler？这种 "框架即函数" 的设计有什么复用优势？

```js
// prefetch.mjs
import { Observable } from './observable.mjs'

function fromEvent(target, type) {
  return new Observable(obs => {
    const h = e => obs.next(e)
    target.addEventListener(type, h)
    // 简化：靠 closed 停止推送即可
  })
}

// 鼠标连续划过多个链接，但只对前 3 个发 prefetch
fromEvent(document, 'mouseover')
  .filter(e => e.target.matches('a[data-prefetch]'))
  .map(e => e.target.href)
  .take(3)
  .subscribe({ next: url => {
    const link = document.createElement('link')
    link.rel = 'prefetch'; link.href = url
    document.head.appendChild(link)
    console.log('prefetched:', url)
  }})
```

**产出可验证**：在 `index.html` 里放 10 个 `<a data-prefetch href="...">`，鼠标依次划过，DevTools Network 应看到前 3 个请求以 Lowest 优先级发出（Priority 列），之后不再新增。

**联动**：一次验证两件事——① 第 3 题 `take` 的"上游取消"是否真的生效（否则你会看到第 4、5 个 link 仍被插入）；② 第 2 板块 `prefetch` 的优先级特征。两个概念一次落地。
