## 🔥 1. 今日技术热点：React Server Components 在非 Next.js 生态的全面落地

**是什么**
RSC（React Server Components）已不再是 Next.js 独家特性。Waku、Remix（Router v7+ 的 single-fetch 架构）、TanStack Start、甚至 Vite 官方实验性 `@vitejs/plugin-rsc` 都开始支持裸 RSC 流式渲染（具体版本待验证）。这意味着你可以不用 Next 的全栈约定，也能用上「组件级别的服务端-客户端边界」。

**解决的旧痛点**
- 传统 SSR + hydrate 的模式必须把整棵树的 JS 都发给客户端，TTI 被大包袱拖垮。
- `getServerSideProps` 类数据获取与组件是割裂的，props 需要手动串联。
- 仅为了"少发几 KB JS"就上微前端或岛屿架构（Islands），架构代价过大。

**底层原理 / 关键设计**
- RSC 把组件分为三类：Server Component（只在服务端执行，产出一棵「序列化虚拟 DOM」）、Client Component（`'use client'`，走传统 CSR/hydrate）、Shared（两端都可运行）。
- 服务端渲染输出不是 HTML 字符串，而是一种**行式 JSON 流**（RSC Wire Format），客户端 Runtime 边收边 reconcile，天然支持 Suspense 流式。
- Client Component 的引用被编译成一个 `$$typeof: client-reference` 的占位符，客户端拿到后按需加载 chunk。
- 这套协议是「渲染结果」的协议，不是「HTML」协议，所以可被 Router 缓存、可被 Prefetch、可和 Server Actions 复用传输层。

**对日常工作的影响**
- 做内容型站点（文档、电商详情、后台表格页）可以把大量"只读展示组件"推到 Server，客户端包体能砍掉一半以上。
- 心智模型变了：`useState` / `useEffect` / 浏览器 API 不能在 Server Component 用；要习惯"数据离组件近、交互才下探到 Client"。
- 调试要熟悉 Wire Format：Chrome DevTools 里看到的 `text/x-component` 响应就是 RSC Payload，排障时要会读它。

## 📘 2. 一个值得掌握的概念：浏览器的 Paint Holding 与 BFCache 的联动

**是什么**
Paint Holding 是浏览器在同源导航时**延迟展示新页面的首帧**、短暂继续显示旧页面的机制，避免"白屏闪烁"。BFCache（Back/Forward Cache）是把整个页面（含 JS 堆、DOM、Timer 冻结状态）缓存到内存，前进/后退秒开。两者看似无关，实则共同支撑了"导航体验"。

**为什么需要**
原始模型是「导航 = 卸载旧文档 + 创建新文档」，中间必然有白屏。白屏是最伤 LCP 和用户感知流畅度的来源之一。Paint Holding 消除短同源跳转的白屏；BFCache 把"前进后退"降为近乎 0 成本。

**怎么实现（关键机制）**
- **Paint Holding**：浏览器用一个"上一页帧缓冲"占位，直到新 Document 的首帧 ready 或超时（Chromium 大约 500ms，待验证）才切换。前提是**同源**导航。
- **BFCache**：进入前触发 `pagehide(persisted=true)`，取出时触发 `pageshow(persisted=true)`。要进入 BFCache，页面不能持有：未关闭的 WebSocket、未结算的 IndexedDB 事务、`unload` 监听器、`Cache-Control: no-store` 响应头等。

**边界与误区**
- SPA 的 router.push 不触发 Paint Holding，它只对**浏览器级导航**生效。
- `beforeunload` 阻止 BFCache 的误解：实际上 Chromium 允许有 `beforeunload`，真正阻止的是 `unload`。
- BFCache 恢复时 `document.visibilityState` 已变化，但一些 Timer/Observer 可能被冻结唤醒，定时逻辑需要在 `pageshow` 校准。
- 使用 Chrome DevTools → Application → Back/forward cache 面板可定位阻止原因。

## 🧩 3. 深度面试题：实现一个支持"结构共享"的不可变更新函数

**题干**
手写 `set(obj, path, value)`，要求：
```js
const state = { user: { name: 'A', addr: { city: 'BJ' } }, list: [1,2,3] }
const next = set(state, ['user', 'addr', 'city'], 'SH')
// next !== state, next.user !== state.user, next.user.addr !== state.user.addr
// 但 next.list === state.list（结构共享：未修改的子树保持引用相等）
```
这是 Immer / Redux Toolkit / Zustand 做浅比较优化的底层能力。

**追问 1**：path 含数组下标（如 `['list', 0]`）怎么办？如何区分"对象字段"与"数组下标"？
**追问 2**：如果 path 中某段不存在，是报错、创建对象、还是创建数组？
**追问 3**：如何扩展成 `setIn(obj, path, updater)`（传函数而非值），并保证 `updater` 不被多次调用？

**参考答案**
```js
function set(obj, path, value) {
  if (path.length === 0) return value
  const [key, ...rest] = path
  const isIndex = typeof key === 'number' || /^\d+$/.test(key)
  const isArr = Array.isArray(obj)
  const base = obj ?? (isIndex ? [] : {})
  const child = base[key]
  const nextChild = set(child, rest, value)
  if (nextChild === child) return obj // 结构共享：无变化则返回原引用
  const clone = isArr ? base.slice() : { ...base }
  clone[key] = nextChild
  return clone
}

// 追问 3：
function setIn(obj, path, updater) {
  const old = path.reduce((o, k) => o?.[k], obj)
  const next = updater(old)          // 只调用一次
  return Object.is(next, old) ? obj  // Object.is 比 === 更安全（NaN）
                              : set(obj, path, next)
}
```

**考察点**：递归 + 结构共享、数组/对象分支、`Object.is` vs `===`、不可变数据的性能本质（为什么 React 浅比较能跳过渲染）、函数式编程里的 lens 思想雏形。

## 🛠️ 4. 新工具/规范/API 速览：View Transitions API Level 2（Cross-document）

**是什么**
Level 1 的 `document.startViewTransition()` 仅支持**同文档**（SPA 内）的状态过渡。Level 2 把它扩展到**跨文档**：多页应用（MPA）之间的页面切换也能用 CSS 做共享元素动画，只要加 `@view-transition { navigation: auto; }` 即可。Chromium 已稳定，Safari/Firefox 跟进中（具体版本待验证）。

**解决什么问题**
过去只有 SPA 才能做"图片从列表飞到详情页"的共享元素动画，MPA 想做就必须变 SPA 或上 Turbo/htmx 之类的框架。Level 2 让传统 MSR（Multi-page SSR）也能有 App 般的转场。

**和已有方案对比**

| 方案 | 代码量 | 是否需 SPA | 共享元素动画 | 首屏性能 | 对 SEO 影响 |
| --- | --- | --- | --- | --- | --- |
| SPA + FLIP 手写 | 高 | 是 | 可 | 一般 | 需 SSR 补偿 |
| Shared Element Transitions（旧提案） | 低 | 是 | 可 | 一般 | 同上 |
| Turbo/htmx 片段替换 | 中 | 否 | 困难 | 好 | 好 |
| **View Transitions L2** | 极低 | **否** | **可** | **好** | **好** |

**现阶段建议**：**立刻学，渐进增强**。写法：
```css
@view-transition { navigation: auto; }
.cover { view-transition-name: cover-img; }
```
不支持的浏览器直接跳过动画，不影响功能。注意：仅限**同源**导航，且不能拦截取消（与 SPA 版本 API 签名不同）。

```js
import { test } from 'node:test'
import assert from 'node:assert'
import { set } from './immutable.mjs'

test('基本更新', () => {
  const s = { a: { b: 1 } }
  const n = set(s, ['a', 'b'], 2)
  assert.strictEqual(n.a.b, 2)
  assert.notStrictEqual(n, s)
  assert.notStrictEqual(n.a, s.a)
})
test('结构共享', () => {
  const s = { a: { b: 1 }, c: [1,2] }
  const n = set(s, ['a', 'b'], 2)
  assert.strictEqual(n.c, s.c) // 未修改的子树应引用相等
})
test('数组下标', () => {
  const s = { list: [1,2,3] }
  const n = set(s, ['list', 1], 99)
  assert.deepStrictEqual(n.list, [1,99,3])
  assert.ok(Array.isArray(n.list))
})
test('路径不存在自动创建', () => {
  const n = set({}, ['a', 'b', 'c'], 1)
  assert.strictEqual(n.a.b.c, 1)
})
```
